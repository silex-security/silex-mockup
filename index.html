Enterprise Infrastructure for AI Agents

What one agent learns becomes knowledge others can build on.

SILEX is a shared, self-evolving ontology and runtime knowledge graph. It turns fragmented business context and execution experience into structured knowledge that agents can reuse, update and reason over. This demo walks the product suite across the agent lifecycle.

Today, forward-deployed engineers translate business intent into agent workflows, one deployment at a time. SILEX makes that execution knowledge transferable, so a new deployment starts from practices that earlier ones validated.

How the check works

Before a consequential action runs, SILEX Runtime assesses it in business context: permissions, business rules, prior steps and expected state changes. It checks in three steps: fixed rules, then a judge model (Jev), then a policy. It then advises the control already in the path, such as an MCP gateway, which lets it run, holds it for a person, or blocks it.

The published L1 classes are distilled from public ontologies — MITRE D3FEND, ATT&CK, ATLAS, UCO and the OWASP GenAI lists — and keep their real identifiers. L1 also holds Silex-authored core concepts, and those, like everything else Silex adds, carry a review grade in the inspector: curated (core concepts, domain packs, components, hazards and mappings), heuristic (keyword-mapped threat placements) or illustrative (registered workflows, the L4 runtime graph and all coverage figures). About Ontology Layers · the tiers, the principle and caveats
Final naming is still pending technical alignment. The four tiers, L1 → L2 → L3 → L4, are presentation groups, not taxonomic ranks: only SUBCLASS_OF asserts that one concept is a kind of another. L1–L3 supply the world model's Schema; L4 supplies illustrative World State instances. Plane size is layout only. Counts are verifiable bundle counts, and component mappings are Silex-authored. This view does not depict the Laws, Objectives or Calibration layers. The build refuses to publish a bundle where a relation breaks its predicate signature, where the display tree or the subclass graph has a cycle, or where a node hangs under a lower tier.
Architecture principle: one federated ontology carries every domain pack; a domain pack is a root of its own whose entities and actions are kinds of general L1 concepts; an agentic component is a kind of a general L1 concept, deployed in the domains where it runs; and the runtime graph is the one place where those semantics meet observed behaviour. Membership, deployment and grouping are navigation, not subsumption. Organisational ownership stays a navigational attribute.

Layer selection is shared with the Ontology Graph tab: pick a layer here and the explorer opens there.

Definitions

Product terminology from the V1 PRD. Metric formulas are still TBD; values on these pages are illustrative — except Blueprint Studio, which computes its results on the declared graph (simulated outcomes, declared adversary model).

Agentic Blueprint

A pre-deployment, user-confirmed representation of an intended agentic workflow, used for simulation and security validation.

Validation

Testing whether unsafe outcomes remain reachable within a workflow or the enterprise environment.

Alternative Path

A different sequence of actions that can reach the same unsafe outcome after another path has been blocked.

Residual Reachability

The remaining ability to reach an unsafe outcome after one or more controls have been applied. Used instead of "residual risk", which is too broad. Formula TBD

Defense Confidence

Confidence that relevant attack or failure paths have been adequately evaluated and mitigated. Formula TBD

Coverage Confidence

Confidence that relevant workflows, paths, scenarios and environment components are sufficiently represented in validation. Formula TBD

Validated Policy Recommendation

A policy candidate already tested in simulation and recommended on security improvement and business impact.
